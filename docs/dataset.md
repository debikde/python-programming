Все CSV сохранены в `data/raw/ntnu/<recording_group>/` без изменения байтов.
`import_manifest.json` сохраняет происхождение из трёх ZIP, размеры и SHA-256

содержат 5 261 656 строк. Для P7 суммируются оба представления, поэтому это
не оценка времени независимых физических сеансов.

## Формат

Одна строка — отсчёт одного сенсора. В CSV 18 числовых колонок:

- `Acc_X`, `Acc_Y`, `Acc_Z` — ускорение с гравитацией, м/с²;
- `FreeAcc_E`, `FreeAcc_N`, `FreeAcc_U` — ускорение без гравитации, м/с²;
- `Gyr_X`, `Gyr_Y`, `Gyr_Z` — угловая скорость, рад/с;
- `Mag_X`, `Mag_Y`, `Mag_Z` — магнитное поле, условные единицы;
- `VelInc_X`, `VelInc_Y`, `VelInc_Z` — приращение скорости, м/с;
- `Steps` — идентификатор цикла шага (stride), локальный для записи;
- `Terrain` — числовой код рельефа;
- `Turn` — признак поворота, по документации 0/1.

Имена файлов кодируют участок, использование опоры `wi`/`wo`, номер повтора
и датчик `PS`/`TH`/`OS`/`TR` (также `OH` у P7_TF); пример `UNwi01PS.csv`.
`Step` — комбинированный маршрут. Встречаются разные регистры и ширина номера
повтора (`SL`/`Sl`, `03`/`3`), поэтому имя не гарантирует уникальность содержимого.

Согласно README источник записан при 100 Гц, сигналы не фильтрованы, записи
синхронизированы и обрезаны, а циклы выделены по Gyr_Y протезированной голени.
CSV не содержит временных меток: анализ использует 100 Гц как предположение,
а фактическую частоту/потери пакетов по имеющимся полям проверить невозможно.

## Словарь рельефа и выявленные ограничения

| Код | Значение README | Наблюдение в предыдущем EDA по P1–P17 |
| --- | --- | --- |
| 1 | Flat | Присутствует на разных маршрутах, включая переходы |
| 2 | Grass | Встречается в GR |
| 4 | Stair ascent | Присутствует |
| 5 | Stair descent | Присутствует |
| 6 | Slope ascent | Присутствует |
| 7 | Slope descent | Присутствует |
| 8 | Gravel | Встречается в UN и CS; смысл требует уточнения |
| 9 | Uneven terrain | Встречается только в GV; смысл требует уточнения |

Не перекодировать 8/9 автоматически. В предыдущем EDA OS и TR были идентичны
побайтно во всех 570 комплектах P1–P17, где присутствует TR; 49 комплектов
P7_TF имеют OH вместо TR. Совпадение вложенных архивов показывает, что новый
источник не меняет эти файлы. Полная когорта проверена в EDA-ноутбуке.
`P11/SLwo03` и `P11/SLwo3` дублируют весь комплект сенсоров.
У P2 есть неверно именованные OS-файлы: группировка согласована по точным
совпадениям с TR и отражена в `filename_grouping_audit.csv`, raw не переименован.
У четырёх комплектов P6 условие опоры `w0` оставлено неизвестным.
У P2/GRwo02 есть Terrain=99 (145 отсчётов PS), у P6/SLwo06 Terrain=0
(126 отсчётов PS). Эти коды не считаются новыми подтверждёнными классами.
В `P13/GRwi01` есть 326 отсчётов с Turn=2 на каждый датчик.
В EDA-ноутбуке по полной когорте OS/TR совпали в 586 из 587 сравнимых
комплектов; оставшееся различие требует отдельной проверки.
У P16 масштаб VelInc/Acc отличается примерно в 2,5 раза, поэтому временные
и спектральные характеристики требуют уточнения. Список проверок и план решения
приведены в [отчёте](eda_report.md).

## Хранение и использование

`data/raw/` — неизменяемые источники; `data/processed/ntnu/trial_registry.csv` —
производный QC-реестр без изменения сигналов. Таблицы и графики EDA находятся
в `artifacts/reports/eda_ntnu/`. Всё содержимое данных и артефактов, кроме
`.gitkeep`, исключено из Git. Команды воспроизведения находятся в README.

Проект предназначен для исследовательской классификации рельефа; это не
клиническая система диагностики. Лицензии кода и текстов проекта не заменяют
условия исходного датасета. При использовании следует сохранять цитирование
источника и документировать все исправления производных данных.
